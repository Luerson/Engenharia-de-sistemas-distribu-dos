# Q9 — Defense in Depth: Microserviços

## a) Dados em repouso

**TDE (Transparent Data Encryption)** protege arquivos/volumes do banco em repouso. É uma camada ampla e útil contra acesso direto ao armazenamento, mas não impede que uma aplicação autorizada consulte os dados.

**Column Encryption** permite proteger campos específicos e é adequada quando apenas determinados atributos possuem sensibilidade elevada. Exige maior gestão de chaves e pode afetar consultas.

**Tokenização** substitui o dado sensível por um token sem valor operacional fora do sistema do provedor. Para dados de cartão, uma estratégia baseada em um provedor especializado de pagamentos, como Stripe, reduz a necessidade de armazenar diretamente o número do cartão no GoFood.

Para este cenário, a arquitetura deve preferir **tokenização e não armazenar o número completo do cartão** no GoFood. TDE pode ser usada como camada adicional para os bancos e Column Encryption pode ser considerada para campos sensíveis que ainda precisem ser armazenados.

## b) Segurança da rede interna

Uma arquitetura possível:

```text
Internet
   |
 HTTPS
   v
[API Gateway]
   |
   +---- TLS/mTLS ----> [Auth Service]
   |
   +---- TLS/mTLS ----> [Orders Service]
   |
   +---- TLS/mTLS ----> [Products Service]
   |
   +---- TLS/mTLS ----> [Payments Service]
                              |
                         Subnet isolada
```

- TLS termina no API Gateway para conexões externas.
- Entre microserviços, utilizar mTLS via service mesh.
- Aplicar autenticação/autorização entre serviços.
- Isolar Payments em uma subnet/rede própria.
- Restringir firewall/security groups para permitir somente fluxos necessários.

## c) Observabilidade

| Evento monitorado | Vulnerabilidade relacionada |
|---|---|
| Muitas tentativas de login do mesmo IP/conta | V18 |
| Tentativas de acesso a `/admin/orders` por usuários não-admin | V10 |
| Grande quantidade de IDs de pedidos diferentes em sequência | V7 |
| Entradas contendo padrões típicos de SQL Injection | V2/V6 |
| Detecção de payloads XSS em comentários | V15 |
| Alterações inesperadas de role/autorização | V10/V13/V14 |
| Erros 500 recorrentes e tentativas de provocar exceções | V20 |
| Requisições HTTP em vez de HTTPS ou configurações TLS inválidas | V11 |

Os logs devem evitar registrar senhas, tokens JWT, números completos de cartão e outros segredos.
